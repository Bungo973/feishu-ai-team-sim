# AI 进度助手

项目助理自己搭的提效工具（工具 3）：一个能对话的飞书机器人（agent）。私聊它随便说，它自己决定查群聊、查表、跑核对还是改表：

- “核对一下” → 把群聊、「任务进度」表、「日报」表放在一起，列出 🔍要核实 / ⏰要催 / ⚠️快到期，每条附原话作依据
- “A4 现在什么情况？群里谁提过？” → 自己去查表、翻群消息再回答
- “A4 王丽确认过了，标成已完成” → 直接改任务表，告诉你旧值 → 新值；说“撤销”就恢复
- 它自己推断出来的改动，会先问你，同意了才改

AI 负责找、查、打字；核实和拍板是人。改表会触发飞书工作流（依赖联动提醒照常生效）。

| 工具 | 作用 |
|---|---|
| get_tasks / get_reports / get_messages | 读任务表、日报表、群聊（可按编号、人、关键词筛） |
| update_task / undo_last_edit | 改任务表（只能改状态、负责人、审核人、两个日期、备注），撤销上一次 |
| run_check | 完整跑一次 AI 进度核对 |

## 和模拟器完全隔离

它是一个独立项目，规则如下：

| 能读 | 不能读 |
|---|---|
| 它所在群的聊天记录（飞书 API） | 模拟器的代码、存档、剧本、导演备注 |
| 能改的只有「任务进度」表的 6 列（飞书 API，有记录可撤销） | 不能删行、加行，不能改别的表 |
| 「任务进度」「日报」两张多维表格（飞书 API） | 任何人的私聊（包括你和同事的私聊） |
| `../shared/clock.jsonl`：现在是哪天几点、上没上班 | 同事的真实进度（只有引擎知道） |

- 代码里不 import 模拟器的任何东西。检查：`uv run python tests/test_isolation.py`
- 唯一从模拟器来的是时钟。模拟时间是压缩的，相当于真实公司里电脑的系统时钟。
- 每次核对的**全部输入**都存在 `核对记录/*-输入.md`，可以打开看它到底看到了什么。

## 怎么跑

`uv run sim serve` 会顺带在后台启动它（日志前缀 `[助手]`），不需要单独开。单独跑：`uv run assistant`。

私聊「AI 进度助手」直接说话。快捷命令：**开启自动 / 关闭自动**（每天中午、下班各推一次核对）、**新对话**（清空它记得的聊天）。

记录：`data/对话.json`（最近 40 句）、`data/改表记录.jsonl`（每次改表的旧值 / 新值）、`核对记录/`（每次核对的输入和结果）。

## 配置（约 20 分钟）

1. 打开 https://open.feishu.cn/app → **创建企业自建应用**，名字叫「AI 进度助手」→ 添加应用能力：**机器人**。
2. **权限管理**，开通（可以批量导入）：
   ```json
   {"scopes": {"tenant": ["im:message", "im:message:send_as_bot", "im:message.p2p_msg:readonly",
                          "im:message.group_at_msg:readonly", "im:chat:readonly", "im:message:readonly",
                          "im:message.group_msg", "im:message.group_msg.include_bot:read",
                          "bitable:app:readonly", "bitable:app"], "user": []}}
   ```
   `im:message.group_msg` 和 `include_bot:read` 是读群里所有消息（包括机器人同事的发言）用的，少了会报 230027。
3. 复制 `.env.example` 为 `.env`，填 App ID / Secret、多维表格链接（带 `?table=` 的任务表）、大模型接口（要支持工具调用）。
4. 先运行一次 `uv run assistant`，再回后台：**事件与回调 → 使用长连接接收事件 → 添加事件「接收消息 v2.0」** → **创建版本并发布**。改了权限或事件都要重新发布。
5. 把它拉进两个群；多维表格右上角"…" → 添加文档应用 → 选它，给**可编辑**。
6. 在飞书里私聊它，发"你好"。

检查隔离：`uv run python tests/test_isolation.py`。
