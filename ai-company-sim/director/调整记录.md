# 与原设定包的差异（含剧透，跑完再看）

实现时审查设定包后做的调整。每条都写了原因。

## 流程

1. **一天拆成"上班 / 下班"两段**（原设计是一次 `next`）。
   原因：原设计里你今天的动作要到第二天早上才生效，变更当天处理、病假当天调度这类"当天决定当天见效"的场景就做不出来。现在：`start` 生成白天消息 → 你工作 → `end` 先评估你今天的动作，再计算今天的真实进度，晚间消息和日报就能反映你当天的干预。
2. **早上的"演习"与兑现**：`start` 时在状态副本上演习一遍今天的工作，把 17:00 前会完成的事写进剧本；`end` 时这些完成会被兑现，避免"早上群里说交了、晚上引擎说没交"的矛盾。
3. **群发言自动采集**（`sim listen`）：解决"机器人只能发不能收"导致评估依赖自述日志的问题。
4. **私聊的模拟时间**：私聊里 `/t 14:30` 或 `sim clock 14:30` 设置，用于判断动作是否发生在事件爆发之前。

## 任务依赖

- A5 依赖改为"A4 审核通过"（原来还依赖 A2 全部完成，而 A2 截止 D7、A5 从 D6 开始，原设计自相矛盾）。
- A14 去掉"预算审批"依赖（不是任务，改由 E04 控制强制插队）。
- B12 不再依赖 A14（直播 D12 才执行完，B12 同日发布，原依赖必然导致断更）；标题改为"发布会预告 + 现场亮点剧透"（原标题在玩家手册里会剧透直播）。
- B13 不依赖 A16（12:00 的现场预热早于 14:00 开场）。
- 依赖默认是"完成即可开工"（不必等审批），标 `!` 的才必须等审批通过（例如 A5 ← A4!）。否则王丽 2 天的审批延迟会让 A0 → A3 → A4 整条链不可能按时。

## 事件

- **E07 借调**：陈悦 D6–D7 每天还剩约 1 小时（原来是 0），对应卡片信号"B06 配图 11:50 才给"。
- **E03 口头任务**：随机为"伴手礼"或"抽奖礼品"；预算科目在玩家手册里改名为"伴手礼及礼品"。
- **E09 病假**：内容影响按事件当天 / 次日实际发布的内容计算（日期 ±1 后仍然成立）。
- **E11 化解 / 减轻**：自动取消 C4、C5（手册下月补），与卡片结局一致。
- **E10 / E12 物料到场**：由 E07、E10、E12 的结果共同决定（`engine.delivery`），而不是单纯按工时推算。
- **结算时间**：动作在事件爆发时刻之后才做的，不算"爆发前完成"；有自定义判定的卡片（E02、E03、E04、E08、E11、E14）按卡片规则。

## 内容发布

- 12:00 的小红书：中午前做完才算准时；下午才好的算"晚发"。
- 20:00 的公众号：小李和陈悦会为当天推送加班（设定包：小李经常熬夜赶稿），20:00 后才好的算"晚发"。
- 临发布才送审的内容，王丽当天审（"先这样发吧"），不按 2 天的默认延迟。

## 第一局之后的修订（2026-10-25）

第一局（seed 1118）玩完后复盘发现的问题和改法。离线对照：`uv run python tests/test_offline.py`。

- **催促对产出为零**（设定包 4.3 只让"被追问"影响排序，不增加工时）：被追问的到期 / 逾期任务，负责人当晚加班 1 小时（每人每周最多 3 次；信任 < 40 不加班）。不改变"超载要靠缩减范围 / 换人 / 改期"——离线对照：只催促的第 3 周周五逾期 14，按工作量缩减范围的是 5–6。
- **超载发现不了**：演员只知道每个任务的进度，不知道自己排不排得过来，被问时只会说"今晚给你"。私聊提示词加了每个人接下来 5 天的真实工作量（还要多少小时 / 有多少小时），揭穿规则加第 4 条：被问到排期、工作量时如实说。
- **没有过程反馈**：导演旁白（notes_for_player）在飞书模式下从来没有发给玩家。现在每个中午和下班，导演私聊一条「导演复盘」：记下的追问、揭穿、生效的调整、上线的改进、加班、信任变化、对风险的有效应对数量（不说是哪张卡、漏了什么）。
- **物料到场时间前后不一致**：E12 的结局描述写死了 `print_delay_to`，引擎实际用 `delivery()`（受 E07 / E10 影响会更晚）。结局描述改用 `{到场}` 占位，统一取 `delivery()`。
- **改进清单外的工具不算数**：手册说"清单以外的改进导演按类似标准判定"，但代码只认 I1–I11。新增 I12 依赖联动提醒、I13 AI 进度核对（效果是真实测量，不改引擎）；清单外的改进由导演输出 `X1 + 名字`，记进 improvements（没有引擎效果，进复盘和结局报告）。
- **判定看实质**：P5 加了一句——不同说法、不同渠道做到了 K 的结果就算，只做一半不算。
- **提前结束时段**：飞书里发"中午 / 下班"时，这个时段还有消息没到会先提醒，发"确定中午 / 确定下班"才结束。
- **日报表字段**：手册里的日报字段和程序写入的字段不一致，统一成 提交人 / 模拟日 / 关联任务 / 今日完成 / 进度 / 明日计划 / 卡点 / 交付物链接；写表时只写表里有的字段。任务表改为按链接里的 `?table=` 找，不再要求表名叫"任务进度"。
